# 신상 식품 조사·완료 검사

## 조사 범위

Browser Use로 실제 페이지를 열어 조사한다. 후보 발견과 원문 검증은 별개다. 날짜를 긴 문장에 넣는 것만으로 기간을 제한했다고 판단하지 않는다.

1. CU, GS25, 세븐일레븐, 이마트24를 **각각 독립 질의**한다. `CU 출시`, `CU 신상품`, `BGF리테일 선보인다`처럼 브랜드 별칭과 동사를 바꿔 보완한다. 여러 브랜드를 한 검색어에 묶지 않는다.
2. `scripts/research_gate.py`의 CATEGORIES 각각을 독립 검색한다. 한 질의에 치킨·버거·피자 등을 모두 묶지 않는다.
3. Google은 최근 3일 범위의 `after:YYYY-MM-DD before:YYYY-MM-DD`(끝 날짜는 다음 날) 등을 사용하고, 네이버 뉴스는 기간 설정과 최신순을 적용한다. 원문 발행일을 최종 기준으로 한다. 정확한 한글 날짜 문구를 필수 키워드로 강제하지 않는다.
4. BGF리테일, GS리테일, 세븐일레븐, 이마트24 공식 홈페이지에서 보도자료/뉴스룸의 **최신 목록을 직접 연다**. 식품음료신문 새상품, 식품저널 신상품, 전자신문 유통·생활 최신 목록도 직접 확인한다. 공식 출처 주소는 실제 검색/사이트 메뉴로 확인하고 추측하지 않는다. 최근 3일 범위를 확인할 때까지 목록 페이지를 넘긴다. 검색결과 페이지를 직접 출처 확인으로 대체하지 않는다.
5. 기사별 실제 URL, 발행일, 브랜드, 상품명, 구매처, 출시일과 검증 문장을 기록한다. 여러 기사가 같은 제품을 다루면 하나의 출시 이벤트로 합친다. 할인 기사가 신제품 출시도 다루면 신제품 자체는 포함하고, 할인만 있는 행사는 제외한다.

## 추출 실패 복구

- 검색 페이지의 전체 링크 앞 18개 등 고정 슬라이스는 금지한다. 메뉴·로그인 링크가 아니라 기사 제목과 연결된 링크를 추출한다.
- Google에서는 h3와 연결된 a를 찾되 하나의 선택자에만 의존하지 않는다. 검색 결과 URL이 Google 리디렉션이면 해당 링크를 브라우저로 열고 실제 목적지 URL을 기록한다.
- `result_count == 0`은 우선 **추출 오류**다. 페이지 전체 텍스트/접근성 트리/스크린샷으로 실제 결과 유무를 확인하고, 선택자를 수정하거나 다른 검색엔진으로 다시 탐색한다.
- 검색 결과가 없는 것으로 완료하려면 다른 질의/엔진에서도 확인하고 두 페이지 모두 실제로 '검색결과 없음' 메시지가 보여야 한다. 캡차, 로딩 중, DOM 불일치는 빈 결과가 아니다.
- 각 배치를 즉시 로컬 JSON/텍스트 파일에 저장한다. 큰 결과를 한 번에 자르거나 누락된 부분을 읽지 않은 채 결론 내리지 않는다.

## 조사 증거와 완료 검사

매 실행에 새 디렉터리 `${HERMES_HOME:-$HOME/.hermes}/cron/state/food-research/YYYY-MM-DD/실행ID/`를 만든다. 브라우저에서 실제 읽은 페이지 전체 텍스트와 추출 후보 목록을 저장하고 `coverage.json`을 갱신한다. 과거 실행의 증거를 복사해 완료 처리하지 않는다. 증거는 공개 사이트에 넣지 않는다.

```json
{
  "date": "실행일 YYYY-MM-DD",
  "searches": [
    {
      "key": "CU",
      "query": "CU 출시 after:시작일 before:종료일",
      "status": "verified",
      "attempts": [
        {"url": "실제로 연 검색 페이지 URL", "result_count": 8, "evidence_file": "/실제/저장한/페이지.txt"}
      ]
    }
  ],
  "sources": [
    {
      "key": "전자신문",
      "mode": "latest_index",
      "status": "verified",
      "attempts": [
        {"url": "실제로 연 해당 매체 최신 목록 URL", "result_count": 10, "evidence_file": "/실제/저장한/최신목록.txt"}
      ]
    }
  ]
}
```

위 숫자는 형식 예시일 뿐이며 실행 때 실제 추출 수로 채운다. 모든 필수 브랜드·카테고리·출처의 개별 기록이 필요하다. 정상 검색은 `verified`와 1건 이상 후보, 진짜 빈 검색은 `empty_verified`와 두 번 이상의 독립 시도 및 각 시도 `explicit_no_results: true`가 필요하다. 접근 오류는 `failed`로 기록한다. 공식 최신 목록은 반드시 실제 사이트여야 한다.

발행/빌드/커밋 전 다음 명령의 종료 코드가 0인지 검사한다.

```bash
python3 scripts/research_gate.py /절대경로/coverage.json --date YYYY-MM-DD
```

미조사 축, 추출 실패, 불충분한 증거가 있으면 검사 도구가 실패한다. 실패 시 해당 축을 보완하고 다시 검사한다. 해결하지 못하면 **정상 완료·신상 없음으로 발행하지 말고** 누락 범위와 이유를 Discord에 보고한다. 상태 파일은 갱신하지 않는다. 실제로 검증한 후보는 내부 증거에 보존해 재조사할 수 있도록 한다.

## 실행 후 회귀 확인

- 편의점 검색을 한 검색어로 묶었는가? 그러면 실패다.
- 빈 DOM 배열을 소식 없음으로 해석했는가? 그러면 실패다.
- 공식·전문지·전자신문 목록을 직접 열었는가?
- 게시된 각 제품에 원문 검증 증거가 있는가?
- 이후 빌드/푸시가 성공한 이벤트만 중복 기록에 추가했는가?

검사 도구는 조사 누락을 검출하지만, 검색엔진 색인 누락이나 증거 자체의 사실성까지 완전히 보장하지는 않는다. 다음 정기 실행의 실제 기록도 확인해야 한다.
